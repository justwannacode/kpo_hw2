# FinTrack 

Приложение учёта личных финансов, реализованное в рамках домашнего задания №2 по курсу "Конструирование программного обеспечения."

## Быстрый запуск

Требования: Python 3.11+

Создать и активировать виртуальное окружение

```
python3 -m venv .venv
source .venv/bin/activate
```

Установить зависимости

```
pip install -U pip
pip install -e ".[dev]"
```

Запустить приложение

```
fintrack
```

## Сценарии

1. Показать счета - вывести все банковские счета и текущие балансы.
2. Создать счет - добавить новый счёт с начальными средствами.
3. Переименовать счет
4. Удалить счет
5. Показать категории - вывести все категории доходов и расходов.
6. Создать категорию
7. Изменить категорию
8. Удалить категорию
9. Показать операции - вывести все финансовые операции.
10. Добавить операцию
11. Удалить операцию
12. Пересчитать баланс счета - обновить баланс на основе операций.
13. Аналитика - рассчитать сальдо (доходы-расходы) и сводка по категориям
14. Экспорт - сохранить данные в CSV, JSON или YAML
15. Импорт - загрузить данные из CSV, JSON или YAML
16. Статистика времени сценариев - показать среднее время выполнения сценариев
17. Выйти - завершить работу

## Структура проекта

```
src/
  fintrack/
    app/
      main.py                   – точка входа, меню управления
    di/
      container.py              – DI-контейнер, связывает зависимости
    domain/
      entities.py               – доменные сущности: BankAccount, Category, Operation
      value_objects.py          – неизменяемые объекты: Money, OperationType, CategoryType
      factories.py              – фабрика создания сущностей
      validators.py             – проверка корректности данных
      repositories.py           – интерфейсы репозиториев
    infrastructure/
      db.py                     – работа с SQLite, инициализация схемы
      repositories_sql.py       – реализация репозиториев на SQL
      proxies.py                – прокси с кешированием
    services/
      facades.py                – фасады для работы с аккаунтами, категориями и операциями (Фасад)
      commands.py               – команды
      analytics.py              – аналитика по операциям
      importers.py              – импорт
      exporters.py              – экспорт
      decorators.py             – замеры времени
pyproject.toml                  - зависимости и настройки проекта
readme.md                       - документация
.gitignore                      - исключения для Git
```
## Соблюдение принципов SOLID

- S — каждый класс отвечает за одну задачу: BankAccount хранит баланс, Factory создаёт сущности и т. д.

- O — легко добавить новый формат импорта/экспорта или новый тип репозитория (например, in-memory) без изменения существующего кода.

- L — все реализации репозиториев могут использоваться взаимозаменяемо через интерфейсы.

- I — интерфейсы разбиты по областям (аккаунты, категории, операции); сервисы зависят только от нужного им интерфейса.

- D — верхний уровень (фасады, команды) зависит от абстракций, а не конкретных SQL-репозиториев.
Все зависимости связываются через DI-контейнер.

## Соблюдение принципов GRASP

- Information Expert — Сущности и фасады владеют логикой, соответствующей их данным
- Creator — Фабрики и фасады создают нужные объекты
- Controller — Команды и меню управляют сценарием
- Low Coupling — DI и интерфейсы репозиториев
- High Cohesion — Каждый слой решает одну задачу
- Polymorphism — Разные форматы импорта/экспорта и типы операций
- Pure Fabrication — Сервисы аналитики, экспорта, прокси
- Indirection — Контейнер и фасады посредничают между слоями
- Protected Variations — Интерфейсы защищают от изменений инфраструктуры

## Использованные паттерны проектирования

| Паттерн         | Где используется                                           | Назначение                                                                          |
|-----------------|------------------------------------------------------------|-------------------------------------------------------------------------------------|
| Команда         | services/commands.py                                       | Инкапсуляция действий пользователя                                                  |
| Фасад           | services/facades.py                                        | Упрощённый интерфейс для доменных операций                                          |
| Прокси          | infrastructure/proxies.py                                  | Кеширование и «ленивые» операции с БД                                               |
| Декоратор       | services/decorators.py                                     | Замер времени выполнения команд                                                     |
| Фабрика         | domain/factories.py                                        | Создание доменных сущностей с валидацией                                            |
| Шаблонный метод | services/importers.py                                      | Единый алгоритм импорта разных форматов                                             |
| Посетитель      | services/exporters.py                                      | Экспорт данных в разные форматы                                                     | 
| Репозиторий     | domain/repositories.py, infrastructure/repositories_sql.py | Предоставляет коллекционно‑подобный интерфейс и изоляцию домена от конкретной СУБД. |
